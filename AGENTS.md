# Project instructions

Read README.md and docs/EDITORIAL.md before changing content. Preserve the project's purpose and the distinction between evidence, proposals, and moonshots. Do not replace the sense collection with a fixed universal hierarchy.

Canonical records live in data/concepts.json. Edit source, then run validation, unit tests and the builder. Commit generated dist files with source changes. No hosted assets, backend or network requests may be required to use the released offline edition.

Keep all meanings and relation notes available in print. Preserve stable IDs; add explicit migration records rather than silently reusing an ID for a different sense. Source review and license checks are required before bulk import. Do not assert educational efficacy based on an attractive interface.
